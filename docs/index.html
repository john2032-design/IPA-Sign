xsigner · developer reference

Signing API

Submit an IPA, certificate and provisioning profile to the zsign worker; follow progress; then retrieve a temporary IPA download or iOS OTA installation link. The service uses Tigris for object storage.

Engine: zsignBase URL: https://xsigner.onrender.comNode.js 22+ / Discord.jsOpenAPI JSON
Access and security: this documentation page is restricted to the configured owner IP. By default, /sign retains the public no-key bot contract and is rate-limited by source IP. If the owner configures API_CLIENTS_JSON, every signing submission must include a valid X-API-Key and follows that client's quota. Job status and results still require the job token.

Quick start #

Send multipart/form-data. Choose exactly one IPA source: a file in ipa or a publicly accessible HTTPS download URL in ipaUrl. The URL need not end in .ipa: signed query-string links, endpoints such as /download?id=123, and safe HTTPS redirects are supported. The P12 and provisioning profile must always be file uploads. Do not manually set the multipart Content-Type header; let your HTTP client create the boundary.

POST/sign202 Accepted when queued

Discord bot compatibility alias: POST /api/v1/discord/sign.

curl -X POST 'https://xsigner.onrender.com/sign' \
  -F 'ipaUrl=https://files.example.net/app.ipa' \
  -F 'p12=@certificate.p12' \
  -F 'mobileprovision=@profile.mobileprovision' \
  -F 'password=YOUR_P12_PASSWORD' \
  -F 'appName=Example App' \
  -F 'bundleId=com.example.app' \
  -F 'bundleVersion=1.2.3'

For a local IPA instead, replace the ipaUrl field with -F 'ipa=@app.ipa'. Never send both fields. API keys are disabled by default; when the owner enables per-bot authentication, add -H 'X-API-Key: YOUR_BOT_KEY' to this command.

Request fields #

Names are case-sensitive. The legacy names in the table are retained for the Discord.js bot sample. The API does not accept URLs for certificates, provisioning profiles, icons or tweaks.

mobileprovisionFileYes*.mobileprovision; max 16 MiB. Alias: profile.

Optional per-bot authentication and quotas #

This feature is opt-in so the already-working Discord bot remains compatible when API_CLIENTS_JSON is unset. When the owner configures this environment variable, all signing submissions must include X-API-Key; missing or unknown keys return HTTP 401 before the API parses uploaded files. Use the key in a server-side bot secret/configuration, never in user input or a public Discord message.

{
  "discord-production": { "key": "REPLACE_WITH_A_UNIQUE_RANDOM_SECRET_OF_32_PLUS_CHARS", "limit": 120, "windowMs": 900000 },
  "discord-staging": { "key": "USE_A_DIFFERENT_RANDOM_SECRET_OF_32_PLUS_CHARS", "limit": 20, "windowMs": 3600000 }
}

Set the JSON as API_CLIENTS_JSON in Render's environment settings. Each object key is a client ID; every client object requires a unique key of at least 32 characters. Optional limit and windowMs override the defaults (120 requests per 15 minutes). The accepted window range is 60 seconds to 24 hours. Invalid configuration prevents the service from starting rather than silently disabling authentication.

Authenticated submissions also share a per-source-IP safety ceiling of 300 per 15 minutes by default (API_SIGN_AUTHENTICATED_IP_LIMIT). Client responses include X-API-Client-Limit, X-API-Client-Remaining and X-API-Client-Reset. A client quota error returns HTTP 429 and code: API_CLIENT_RATE_LIMITED, plus Retry-After. API key authentication uses X-API-Key, separate from the Bearer job token used for polling. Keys are compared by hash and are not stored in job manifests or logged.

Important: Leave API_CLIENTS_JSON unset to keep current bot compatibility. When you enable it, add the matching apiKey option to your bot's submitAndPollXsign call (for example apiKey: process.env.XSIGNER_API_KEY). Per-client quota counters are in-memory and reset on restart; use a shared store before running multiple service instances.

Signing lifecycle #

Performance: IPA output uses ZSIGN_ZIP_LEVEL=1 by default for faster archiving than maximum compression. Set it to 0 for no compression (fastest archive step, but potentially larger uploads) or 2–9 to prioritize output size. Concurrency defaults to one signing job unless MAX_CONCURRENT_JOBS is set. Tigris input objects upload in small parallel batches; large Tigris downloads use 32 MiB HTTP byte ranges with up to four ranges in flight. Tune with PART_SIZE_BYTES, TIGRIS_UPLOAD_QUEUE_SIZE, TIGRIS_OBJECT_TRANSFER_CONCURRENCY, TIGRIS_DOWNLOAD_CHUNK_SIZE_BYTES and TIGRIS_DOWNLOAD_CONCURRENCY. Signed result downloads go directly from Tigris to the caller.

  1. Validate and queue. The server checks file names, file limits, the public HTTPS URL and metadata, then uploads assets to private Tigris storage. An accepted job gets a unique jobId and a secret jobToken.
  2. Prepare the worker workspace. Uploaded input objects are streamed from Tigris to temporary local files. For ipaUrl, the IPA is streamed directly from the remote host into the temporary workspace.
  3. Sign with zsign. The worker applies app name, bundle ID, version, icon, and optional tweak injection. A .deb is extracted and any compatible contained dylibs are injected.
  4. Upload the result. The signed IPA is multipart-uploaded to Tigris; input certificate/profile/tweak objects are cleaned up after processing.
  5. Poll and install. Poll the status URL using the job token. On completion, the status response includes a temporary download URL and, when a bundle ID is available, an OTA link.

Endpoints #

GET/JSON API summary

Returns the service name, signing engine, input rule and core endpoint list.

GET/healthzRender readiness

Configured as the Render service health check. Reports the required configuration flags. Returns HTTP 200 when ready or HTTP 503 when a required component is missing. /health remains an alias.

GET/healthz/dependenciesCached dependency diagnostics

Performs cached, bounded checks for the zsign executable, real Tigris bucket access, writable workspace, job-encryption configuration, and Redis when shared-queue mode is enabled. It returns HTTP 200 or 503 plus boolean checks; it does not return credentials or connection strings.

GET/api/ops/metricsOwner-only metrics

Restricted to the configured owner IP. Returns queue mode/depth, active jobs, concurrency, process uptime, scratch-disk available/total bytes and usage percentage, and result-retention configuration. Disk information is observational only: this endpoint does not add capacity limits or reject submissions.

GET/api/v1/discord/healthBot health check

Returns a status value and dependency summary. status is ok only when the signer binary and required server configuration are present; otherwise the endpoint returns a degraded status.

POST/signSubmit signing job

Multipart fields documented above. The equivalent Discord alias is POST /api/v1/discord/sign. No API key is required by default. If API_CLIENTS_JSON is configured, a valid X-API-Key is required.

GET/api/jobs/{jobId}?after=0Poll state / logs / result

Send Authorization: Bearer {jobToken}. The after query parameter is the last log sequence ID you processed; use 0 for all retained logs. Status requests return the current phase, progress and new logs.

curl 'https://xsigner.onrender.com/api/jobs/JOB_ID?after=0' \
  -H 'Authorization: Bearer JOB_TOKEN'
POST/api/jobs/{jobId}/download-urlMint direct download URL

Requires the job token. Returns {"url":"https://...","expiresIn":123,"expiresAt":"2026-10-21T20:00:00.000Z","expiresAtMs":1792612800000}. The timestamps reflect actual retention, not a guaranteed full 10 minutes. Returns 409 if the job is not complete, or 410 after retention expires.

POST/api/jobs/{jobId}/ota-urlMint OTA install URL

Requires the job token. Returns the app metadata plus manifestUrl, installUrl, expiresAt (ISO-8601) and expiresAtMs. Requires a Bundle ID.

GET/ota/{jobId}/{token}/manifest.plistiOS OTA manifest

Used by iOS after opening the itms-services:// install URL. Returns an XML property list; it is not a JSON endpoint. The embedded signed IPA URL expires with the signed result.

GET/sign405 Method Not Allowed

Use POST for signing. Other unknown paths return JSON 404, except the owner-only /doc reference page and its OpenAPI file.

Errors and status codes #

HTTPMeaningWhat to do
400Bad input; invalid URL; unsupported signer; missing IPA, P12 or profile; invalid metadata/file extension.Correct the multipart fields. Use only ipa or ipaUrl; the P12/profile must be files.
401Per-bot authentication is enabled but X-API-Key is missing or invalid.Send the matching bot key from secure server-side configuration, or leave API-key mode disabled while migrating the bot.
404Unknown route, invalid job ID, missing job, or missing/incorrect job token.Verify the ID and send Authorization: Bearer JOB_TOKEN. Job access failures intentionally do not disclose whether a job exists.
405Wrong method, notably GET /sign.Submit signing requests with POST.
409Download or OTA is not ready yet; or OTA cannot be generated without a Bundle ID.Poll until completed or re-submit with a Bundle ID.
410Signed IPA has expired and was deleted.Sign again. Retention defaults to 10 minutes and is configurable with SIGNED_IPA_TTL_MINUTES (1–60 minutes); always use the returned expiry timestamp.
413Uploaded file is above its field's byte limit.Use a smaller file or a direct public ipaUrl if the IPA is the large input.
429Too many signing requests or status/action requests.Respect rate limits and retry with backoff. The default anonymous sign limit is 30 submissions per source IP per 15 minutes; authenticated clients can also hit their per-client quota or the authenticated-IP safety ceiling.
500Unexpected server error.Retry cautiously and inspect Render application logs.
503Tigris, signer configuration, encryption, Redis quota/queue, or URL generation unavailable.Check /healthz for readiness and /healthz/dependencies for cached checks. Use the returned requestId to correlate Render logs.
429Source-IP request limit or per-bot quota has been exceeded.Respect Retry-After and use exponential backoff. Per-client quota enforcement is shared across instances when Redis mode is active.
200 + status=failedSigning worker started but failed while downloading, unpacking, modifying or signing.Read the poll response's error and latest logs entry. HTTP 200 only means the polling request succeeded.
Remote IPA URL returns HTTP 403

A 403 means the remote file host refused xsigner's download. The source host may require login, cookies, a browser challenge, a fresh direct-download URL, or documented hotlink authorization. Use a direct public HTTPS URL which works from a server, or adjust your own source host's documented allowlist/headers. Tigris does not bypass the source host's access controls.

Discord.js / Node.js integration #

The project includes examples/discord-sign-api-client.js, exporting submitAndPollXsign(input). Copy the helper into your bot repository or vendor it as an ES module. It accepts Discord attachment objects with url and name, submits form data, polls with the job token and returns a flattened result for the response code in your bot.

import { submitAndPollXsign, wrapOtaInstallUrl } from './discord-sign-api-client.js';

const signed = await submitAndPollXsign({
  apiBase: 'https://xsigner.onrender.com',
  ipaUrl: 'https://cdn.example.net/app.ipa', // OR pass ipa: attachment
  certificate: certAttachment,               // .p12/.pfx attachment
  profile: profileAttachment,                // .mobileprovision attachment
  password: p12Password,
  appName: 'Example App',
  bundleId: 'com.example.app',
  version: '1.2.3',
  onProgress: async job => {
    // Update the Discord interaction/reply when stage or progress changes.
    console.log(job.stage, job.progress, job.message);
  }
});

console.log(signed.downloadUrl); // temporary .ipa download
console.log(signed.otaUrl);      // itms-services:// install link
console.log(wrapOtaInstallUrl(signed.otaUrl)); // optional OTA landing-page wrapper

When API-key mode is enabled, pass the key with apiKey: process.env.XSIGNER_API_KEY. Leave it unset while API-key mode is disabled. For IPAs over 500 MiB, the included helper recommends ipaUrl to avoid buffering the complete IPA in the Discord bot process. The server itself accepts streamed remote IPA files up to the configured 4 GiB limit. ipaUrl can be any direct public HTTPS download URL, including signed/query-string links, extensionless /download endpoints, and supported HTTPS redirects, without interactive authentication.

Legacy bot: the API accepts certificate/profile/tweaks field names and includes response aliases such as job_id, progress_url, download_url and ota_url. New bot code should poll with the returned jobToken. If the legacy bot submits an Authorization bearer, the API supports that same bearer for polling only the job created by that request.

Operations, diagnostics and scaling #

Every JSON response includes requestId and X-Request-ID. Include that identifier when troubleshooting; never post API keys, job tokens or P12 passwords.

Remote URL fetches pin the validated DNS address to the outgoing HTTPS connection, check non-public IPv4/IPv6 ranges, and revalidate each redirect. This reduces DNS-rebinding/SSRF risk. The URL path does not need a .ipa suffix; the server uses a safe local fallback filename when needed. These checks cannot make an access-restricted source host downloadable; HTTP 401/403 still requires a direct link that the worker can access.

For multi-instance mode, use a Redis-compatible Render Key Value store, configure the same REDIS_URL on the API and worker services, and set MANIFEST_STORAGE=s3 everywhere. Set RUN_SIGNING_WORKER=false on the HTTP API and RUN_SIGNING_WORKER=true on private background worker(s). Redis-backed BullMQ coordinates jobs and quotas; Tigris becomes the authoritative shared manifest store. See docs/SCALING.md in the project ZIP. The standard Blueprint remains single-service by default and does not create billable Redis resources.

The deeper diagnostic endpoint is cached for 15 seconds by default. /healthz remains the lightweight Render probe; /healthz/dependencies can check Tigris availability and should not be used as a high-frequency liveness loop.

Owner-only /api/ops/metrics reports queue depth and operational disk statistics. Render logs include structured job-start, job-completion and job-failure events with queue wait, elapsed time, result size, phase, failure code and request ID. Do not share API keys, tokens or certificate passwords in log excerpts.

Storage, expiry and operational limits #

Private source assets

IPA file uploads, certificate/profile files and tweak assets are stored privately in Tigris while the worker needs them, then removed after processing.

Signed result TTL

The signed IPA is deleted from Tigris after the configured SIGNED_IPA_TTL_MINUTES window (default 10, safe range 1–60). The completion response includes resultExpiresAt and resultExpiresAtMs; download and OTA URL responses include expiresAt and expiresAtMs. URLs cannot outlive that deadline.

Temporary workspace

zsign requires local filesystem capacity to unpack, patch and archive IPA contents. Tigris is object storage, not a drop-in filesystem for zsign's working directory. Large apps may need several times their IPA size in scratch space.

Remote URL restrictions

Only HTTPS URLs resolving to public IPs are accepted; each destination is pinned to the validated DNS result and each redirect is re-resolved. Private, special-use and localhost address ranges are blocked to reduce SSRF risk.

Default server limits: IPA 4 GiB; certificate/profile/icon 16 MiB each; .deb 256 MiB; .dylib 128 MiB; 30 anonymous signing submissions per source IP per 15 minutes; authenticated clients default to 120 submissions per client per 15 minutes plus a 300-per-IP backstop; one active signing job at a time unless MAX_CONCURRENT_JOBS is changed. A submitted Discord app can have a lower attachment limit imposed by Discord or the included helper; use ipaUrl for a very large source.

Keep Tigris credentials, JOB_ENCRYPTION_KEY, API_CLIENTS_JSON and bot API keys in secret environment settings, never in bot source control. The job token grants access to status and results for its job, so don't post it publicly or log it in a public channel.
