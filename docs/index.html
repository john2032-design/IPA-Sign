xsigner · developer reference

Signing API

Submit an IPA, certificate and provisioning profile to the zsign worker; follow progress; then retrieve a temporary IPA download or iOS OTA installation link. The service uses Tigris for object storage.

Engine: zsignBase URL: https://xsigner.onrender.comNode.js 22+ / Discord.jsOpenAPI JSON
Access and security: this documentation page is restricted to the configured owner IP. The /sign API itself is not owner-IP locked and does not require an API key. Submission is public and rate-limited by source IP; job status and results require the job token.

Quick start #

Send multipart/form-data. Choose exactly one IPA source: a file in ipa or a publicly accessible, direct HTTPS URL in ipaUrl. The P12 and provisioning profile must always be file uploads. Do not manually set the multipart Content-Type header; let your HTTP client create the boundary.

POST/sign202 Accepted when queued

Discord bot compatibility alias: POST /api/v1/discord/sign.

curl -X POST 'https://xsigner.onrender.com/sign' \
  -F 'ipaUrl=https://files.example.net/app.ipa' \
  -F 'p12=@certificate.p12' \
  -F 'mobileprovision=@profile.mobileprovision' \
  -F 'password=YOUR_P12_PASSWORD' \
  -F 'appName=Example App' \
  -F 'bundleId=com.example.app' \
  -F 'bundleVersion=1.2.3'

For a local IPA instead, replace the ipaUrl field with -F 'ipa=@app.ipa'. Never send both fields.

Request fields #

Names are case-sensitive. The legacy names in the table are retained for the Discord.js bot sample. The API does not accept URLs for certificates, provisioning profiles, icons or tweaks.

FieldTypeRequiredAccepted formats / behavior
ipaFileOne of ipa/ipaUrl.ipa file; default size cap 4 GiB.
ipaUrlText URLOne of ipa/ipaUrlDirect public HTTPS URL accessible from Render without interactive login, cookies or CAPTCHA. This is the only source URL field.
p12FileYes*.p12 or .pfx; max 16 MiB. Alias: certificate.
mobileprovisionFileYes*.mobileprovision; max 16 MiB. Alias: profile.
passwordTextNoP12 password. Use an empty value for an unencrypted certificate.
iconFileNoPNG image, max 16 MiB. Forwarded to zsign to replace the primary app icon.
appNameTextNoDisplay-name override, max 200 characters. Aliases: app_name, bundleName, bundle_name.
bundleIdTextNoBundle identifier override, e.g. com.example.app. Alias: bundle_id.
bundleVersionTextNoBundle version override. Alias: bundle_version, version.
debFileNo.deb package, max 256 MiB. Extracts compatible .dylib files for injection.
dylibFileNo.dylib, max 128 MiB. Injected directly. May be used with deb.
tweaksFile(s)NoLegacy Discord bot field for up to two .deb/.dylib files; max 256 MiB per multipart parser and validated by extension.
injectExtensionsText booleanNoSet true, 1 or yes to also inject dylibs into app extensions using zsign's -P option.
signerTextNoOnly zsign is supported. Requests for rcodesign return 400 instead of silently using the wrong engine.

* Required file name fields accept either the canonical p12/mobileprovision or bot-compatible certificate/profile aliases. Do not send a URL for these assets.

Signing lifecycle #

  1. Validate and queue. The server checks file names, file limits, the public HTTPS URL and metadata, then uploads assets to private Tigris storage. An accepted job gets a unique jobId and a secret jobToken.
  2. Prepare the worker workspace. Uploaded input objects are streamed from Tigris to temporary local files. For ipaUrl, the IPA is streamed directly from the remote host into the temporary workspace.
  3. Sign with zsign. The worker applies app name, bundle ID, version, icon, and optional tweak injection. A .deb is extracted and any compatible contained dylibs are injected.
  4. Upload the result. The signed IPA is multipart-uploaded to Tigris; input certificate/profile/tweak objects are cleaned up after processing.
  5. Poll and install. Poll the status URL using the job token. On completion, the status response includes a temporary download URL and, when a bundle ID is available, an OTA link.

Endpoints #

GET/JSON API summary

Returns the service name, signing engine, input rule and core endpoint list.

GET/healthzRender readiness

Configured as the Render service health check. Reports zsign presence, Tigris configuration and job-encryption configuration. Returns HTTP 200 when ready or HTTP 503 when a required component is missing. /health remains an alias.

GET/api/v1/discord/healthBot health check

Returns a status value and dependency summary. status is ok only when the signer binary and required server configuration are present; otherwise the endpoint returns a degraded status.

POST/signSubmit signing job

Multipart fields documented above. The equivalent Discord alias is POST /api/v1/discord/sign. No API key or owner IP is required for submission.

GET/api/jobs/{jobId}?after=0Poll state / logs / result

Send Authorization: Bearer {jobToken}. The after query parameter is the last log sequence ID you processed; use 0 for all retained logs. Status requests return the current phase, progress and new logs.

curl 'https://xsigner.onrender.com/api/jobs/JOB_ID?after=0' \
  -H 'Authorization: Bearer JOB_TOKEN'
POST/api/jobs/{jobId}/download-urlMint direct download URL

Requires the job token. Returns {"url":"https://...","expiresIn":123}. Returns 409 if the job is not complete, or 410 after retention expires.

POST/api/jobs/{jobId}/ota-urlMint OTA install URL

Requires the job token. Returns the app metadata plus manifestUrl, installUrl and expiresAt. Requires a Bundle ID.

GET/ota/{jobId}/{token}/manifest.plistiOS OTA manifest

Used by iOS after opening the itms-services:// install URL. Returns an XML property list; it is not a JSON endpoint. The embedded signed IPA URL expires with the signed result.

GET/sign405 Method Not Allowed

Use POST for signing. Other unknown paths return JSON 404, except the owner-only /doc reference page and its OpenAPI file.

Errors and status codes #

HTTPMeaningWhat to do
400Bad input; invalid URL; unsupported signer; missing IPA, P12 or profile; invalid metadata/file extension.Correct the multipart fields. Use only ipa or ipaUrl; the P12/profile must be files.
404Unknown route, invalid job ID, missing job, or missing/incorrect job token.Verify the ID and send Authorization: Bearer JOB_TOKEN. Job access failures intentionally do not disclose whether a job exists.
405Wrong method, notably GET /sign.Submit signing requests with POST.
409Download or OTA is not ready yet; or OTA cannot be generated without a Bundle ID.Poll until completed or re-submit with a Bundle ID.
410Signed IPA has expired and was deleted.Sign the app again. Signed results are retained for 10 minutes after completion.
413Uploaded file is above its field's byte limit.Use a smaller file or a direct public ipaUrl if the IPA is the large input.
429Too many signing requests or status/action requests.Respect rate limits and retry with backoff. The default sign limit is 30 submissions per source IP per 15 minutes.
500Unexpected server error.Retry cautiously and inspect Render application logs.
503Tigris, signer configuration, encryption configuration, or URL generation unavailable.Check /healthz, Render env variables, Tigris credentials/bucket permissions, and the zsign binary.
200 + status=failedSigning worker started but failed while downloading, unpacking, modifying or signing.Read the poll response's error and latest logs entry. HTTP 200 only means the polling request succeeded.
Remote IPA URL returns HTTP 403

A 403 means the remote file host refused xsigner's download. The source host may require login, cookies, a browser challenge, a fresh direct-download URL, or documented hotlink authorization. Use a direct public HTTPS URL which works from a server, or adjust your own source host's documented allowlist/headers. Tigris does not bypass the source host's access controls.

Discord.js / Node.js integration #

The project includes examples/discord-sign-api-client.js, exporting submitAndPollXsign(input). Copy the helper into your bot repository or vendor it as an ES module. It accepts Discord attachment objects with url and name, submits form data, polls with the job token and returns a flattened result for the response code in your bot.

import { submitAndPollXsign, wrapOtaInstallUrl } from './discord-sign-api-client.js';

const signed = await submitAndPollXsign({
  apiBase: 'https://xsigner.onrender.com',
  ipaUrl: 'https://cdn.example.net/app.ipa', // OR pass ipa: attachment
  certificate: certAttachment,               // .p12/.pfx attachment
  profile: profileAttachment,                // .mobileprovision attachment
  password: p12Password,
  appName: 'Example App',
  bundleId: 'com.example.app',
  version: '1.2.3',
  onProgress: async job => {
    // Update the Discord interaction/reply when stage or progress changes.
    console.log(job.stage, job.progress, job.message);
  }
});

console.log(signed.downloadUrl); // temporary .ipa download
console.log(signed.otaUrl);      // itms-services:// install link
console.log(wrapOtaInstallUrl(signed.otaUrl)); // optional OTA landing-page wrapper

For IPAs over 500 MiB, the included helper recommends ipaUrl to avoid buffering the complete IPA in the Discord bot process. The server itself accepts streamed remote IPA files up to the configured 4 GiB limit. ipaUrl must point to a direct public HTTPS download without interactive authentication.

Legacy bot: the API accepts certificate/profile/tweaks field names and includes response aliases such as job_id, progress_url, download_url and ota_url. New bot code should poll with the returned jobToken. If the legacy bot submits an Authorization bearer, the API supports that same bearer for polling only the job created by that request.

Storage, expiry and operational limits #

Private source assets

IPA file uploads, certificate/profile files and tweak assets are stored privately in Tigris while the worker needs them, then removed after processing.

Signed result TTL

The signed IPA is deleted from Tigris about 10 minutes after completion. Download and OTA URLs cannot outlive that deadline.

Temporary workspace

zsign requires local filesystem capacity to unpack, patch and archive IPA contents. Tigris is object storage, not a drop-in filesystem for zsign's working directory. Large apps may need several times their IPA size in scratch space.

Remote URL restrictions

Only HTTPS URLs resolving to public IPs are accepted; each redirect is re-validated. Private network and localhost addresses are blocked to reduce SSRF risk.

Default server limits: IPA 4 GiB; certificate/profile/icon 16 MiB each; .deb 256 MiB; .dylib 128 MiB; 30 signing submissions per source IP per 15 minutes; one active signing job at a time unless MAX_CONCURRENT_JOBS is changed. A submitted Discord app can have a lower attachment limit imposed by Discord or the included helper; use ipaUrl for a very large source.

Keep Tigris credentials and JOB_ENCRYPTION_KEY in Render's environment settings, never in bot source control. The job token grants access to status and results for its job, so don't post it publicly or log it in a public channel.
