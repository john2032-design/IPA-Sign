# xsigner — Render + Backblaze B2 + zsign

A Render-hosted iOS IPA signing website. The browser uploads directly to a **private Backblaze B2 bucket** using presigned multipart URLs. Render downloads the files into a temporary workspace, runs the upstream [`zhlynn/zsign`](https://github.com/zhlynn/zsign) CLI, uploads the signed IPA, and issues a temporary download URL.

## What this ZIP includes

- **Actual signing engine:** Docker clones and compiles the upstream `zhlynn/zsign` v1.1.2 tag for Linux. A small build-time patch only adds operation-count progress lines to the CLI output; signing decisions and cryptographic work remain in upstream zsign.
- **Signing inputs:** required `.ipa`, `.p12`/`.pfx`, and `.mobileprovision` files. P12 password is optional.
- **Advanced options:** optional Bundle ID (`-b`), App name (`-n`) and Version (`-r`), matching the upstream CLI switches.
- **Progress:** browser uploads and server downloads use measured byte counts. The pinned source build also reports completed Mach-O and bundle-signing operations, which drive the live percentage during signing; CLI archive milestones finish the meter.
- **Live terminal popup:** server-persisted zsign stdout/stderr is streamed to the browser by the authenticated job polling endpoint. P12 passwords are redacted from captured output.
- **Blue-and-white branding:** the provided image URL is used for the logo, favicon, Apple touch icon and social preview.

## Architecture

- **Render Web Service:** website, API, job queue, and compiled `zsign` executable.
- **Backblaze B2 (S3-compatible API):** private input/output storage and encrypted job manifests.
- **Multipart uploads:** large files upload directly from the browser to B2; Render is not the 4 GiB upload proxy.
- **Background worker:** jobs are queued and polled, so the signing operation does not keep a browser HTTP request open.
- **Temporary processing storage:** a Render disk mounted at `/data` holds inputs and the signed output only while the job is running.

## Render deployment

The included `render.yaml` defines a Docker web service named **`xsigner`** in Ohio, a `/health` check, a 40 GB persistent work disk, environment variables, and a generated job encryption key. Render requires these files in a connected Git repository.

1. Push this folder to your Git repository.
2. In Render, create a Blueprint from that repository (or create a Docker web service with equivalent settings).
3. Provide `B2_KEY_ID` and `B2_APPLICATION_KEY` when prompted. Render generates `JOB_ENCRYPTION_KEY`.
4. Deploy and wait until the service is **Live**. Check `/health`; it should report `signer: "zsign"`, `signerPresent: true`, storage configured, and encryption configured.
5. Set the B2 CORS rule from `b2-cors.json` before attempting an upload. Use the exact deployed site origin if the hostname changes.

The Docker build compiles the pinned upstream zsign v1.1.2 source with the Linux Makefile and applies `scripts/patch-zsign-progress.mjs`. That patch emits a counter after each successful per-file or bundle-signing operation for the live percentage; it does not change the signing logic. The upstream MIT license notice is included in the runtime image. On Render the executable is installed at `/usr/local/bin/zsign`, controlled by `ZSIGN_BIN`.

## Backblaze B2 setup

Create/use a **private** B2 bucket named `xsigner` in `ca-east-006` (or update the environment to your own bucket and region):

```text
B2_ENDPOINT=https://s3.ca-east-006.backblazeb2.com
B2_REGION=ca-east-006
B2_BUCKET=xsigner
B2_KEY_ID=<bucket-scoped application key ID>
B2_APPLICATION_KEY=<bucket-scoped application key>
```

Use a bucket-scoped application key with only the read, write, delete and list permissions required by this service. Do not put credentials in the front end or source control, and do not make the bucket public.

### CORS

Set the bucket CORS rules to `b2-cors.json`. It permits upload requests from `https://xsigner.onrender.com` and exposes `ETag` for multipart completion. Update `AllowedOrigins` to your exact HTTPS hostname if needed. For local development only, add your local origin temporarily.

### Lifecycle and retention

Configure a B2 lifecycle rule to abort incomplete multipart uploads after one day. The service removes the source IPA, P12 and profile after signing succeeds or fails. Signed results and job manifests expire after the configured job TTL (24 hours by default); presigned download links expire after one hour. Abandoned upload jobs expire automatically.

## API overview

- `GET /health` — service, zsign executable, storage and encryption readiness.
- `GET /api/config` — public upload-size configuration.
- `POST /api/jobs` — create a job and multipart uploads; returns a one-time job token.
- `POST /api/jobs/:id/part-urls` — mint short-lived multipart upload URLs.
- `POST /api/jobs/:id/complete-upload` — complete and size-verify each object.
- `POST /api/jobs/:id/sign` — queue signing with optional password and optional metadata overrides.
- `GET /api/jobs/:id?after=<log-id>` — authenticated job status plus only new console lines.
- `POST /api/jobs/:id/download-url` — request a one-hour signed IPA download URL.

All job endpoints other than creating the job require the bearer token. The browser keeps it in page memory, never in the download URL. Passwords are encrypted in the private manifest while queued, passed to the upstream CLI only when nonempty, redacted from captured output and cleared from manifests after signing succeeds or fails.

## Security notes

- Keep B2 private and store its credentials only in Render environment variables.
- `/health` confirms the zsign binary exists but does not perform a real B2 write/read test.
- Anonymous uploads/signing can consume CPU and storage. Keep IP rate limits enabled, use `MAX_CONCURRENT_JOBS=1` until load tested, and consider an access gate or quota before public launch.
- A restarted worker can recover queued/interrupted jobs from B2 manifests. Do not rotate `JOB_ENCRYPTION_KEY` while jobs are queued.
- zsign accepts the P12 password via the `-p` argument when supplied; that argument is not logged by this service, and captured output redacts the password.
- Use certificates/profiles you are authorized to use. Successful signing does not guarantee OTA installation; the device, profile, certificate, bundle ID and entitlements must match.

## Local checks

```bash
npm install
npm run check
npm start
```

The API can start without B2 credentials so `/health` is available, but uploads return a configuration error until B2 environment variables and the encryption key are configured. A Docker build needs network access to clone the pinned upstream zsign release.
